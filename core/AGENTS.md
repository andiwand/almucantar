# AGENTS.md — the core

The C++20 library that calculates the sun and the projection, with its bindings.
The design is in [`../PLAN.md`](../PLAN.md) section 5.

## Directory map

| Path | What |
|---|---|
| `src/almucantar/*.hpp`, `*.cpp` | The public API. `almucantar.hpp` includes all public headers. Only these headers are installed. |
| `src/almucantar/terrain.*` | The terrain horizon: the profile from a DEM grid and the visible sunrise and sunset. The ray march and the grid sampling are in the anonymous namespace of `terrain.cpp`. |
| `src/almucantar/sky.*` | The planets, the galactic system (the Milky Way), and the stars of a catalogue (`StarCatalog`, `star_positions()`), from Astronomy Engine. starradar uses them (PLAN.md 14.2). The Python and the WASM bindings have them; the AAR and the Swift package get them when the native apps of starradar need them. |
| `src/almucantar/internal/` | Everything else: the solar models (`SolarModelImpl`, `NoaaModel`, `AstronomyEngineModel`, and the moon in `astronomy_engine.cpp`), refraction, events, paths, the WMM, the projection (`Projector`), the search, the heading filter (in `heading.cpp`), numerics (`bisect`, `golden_min`), vectors, time, validation. |
| `src/almucantar/internal/wmm_coefficients.cpp` | Generated by `tools/wmm/generate_wmm.py`. Do not edit it by hand. |
| `test/src/` | Catch2 tests of the public API. |
| `test/src/internal/` | Catch2 tests of internal code, where the internals are the subject (the model, the refraction). |
| `test/data/` | Reference data: JPL Horizons (`test/tools/fetch_horizons.py` makes it) and the official WMM2025 test values. |
| `tools/wmm/` | The WMM2025 coefficient file, its source, and the generator. See its `README.md` for WMM2030. |
| `python/` | The Python binding. See [`python/AGENTS.md`](python/AGENTS.md). |
| `android/` | The JNI binding and the AAR. See [`android/AGENTS.md`](android/AGENTS.md). |
| `wasm/` | The WebAssembly binding and the npm package. See [`wasm/AGENTS.md`](wasm/AGENTS.md). |
| `apple/` | The C API and the Swift package (`Package.swift` at the root). See [`apple/AGENTS.md`](apple/AGENTS.md). |
| `src/almucantar/internal/geotiff.*` | The GeoTIFF reader of the elevation tiles. The file comes from the network, so each read checks its range. `test/tools/make_geotiff.py` makes the test files in `test/data/geotiff/`. |
| `third_party/astronomy-engine/` | Astronomy Engine (MIT), vendored. Do not edit; see its `README.md`. |
| `cmake/` | Compiler options and the check of the public headers. |

## Build and test

Run these commands in `core/`.

1. Install the dependencies. Add `-o "&:with_python=True"` for the Python binding:

   ```sh
   conan install . --build=missing -s build_type=Debug
   ```

2. Configure. Add `-DALMUCANTAR_SANITIZE=ON` for ASan and UBSan:

   ```sh
   cmake --preset conan-debug -DALMUCANTAR_WARNINGS_AS_ERRORS=ON
   ```

3. Build:

   ```sh
   cmake --build --preset conan-debug
   ```

4. Run the tests. With the Python binding, CTest also runs pytest:

   ```sh
   ctest --preset conan-debug --output-on-failure
   ```

5. Run clang-tidy on a file. CI runs it on `src/`, `python/src/`, and `android/jni/`:

   ```sh
   ../.venv/bin/clang-tidy -p build/Debug src/almucantar/sun.cpp
   ```

CMake options: `ALMUCANTAR_TESTS`, `ALMUCANTAR_PYTHON`, `ALMUCANTAR_JNI`, `ALMUCANTAR_WASM`, `ALMUCANTAR_APPLE`, `ALMUCANTAR_WARNINGS_AS_ERRORS`,
`ALMUCANTAR_SANITIZE`. Add a new `.cpp` to `ALMUCANTAR_SOURCE_FILES`.

## The public API

- The public API is small: value types (plain structs) and free functions. It has no
  class hierarchies, no templates, no callbacks, no handles, and no state. So a
  binding only converts structs and arrays.
- A public header never includes an internal header. The test
  `public_headers_do_not_include_internal_headers` checks this. Each public header
  must also compile alone with only the public headers on the include path. The
  target `almucantar_public_header_check` checks this.
- A function becomes public only if an app needs it. Then add it to every binding,
  with a test in each binding, and add an entry to `CHANGELOG.md`.
- A public function validates its arguments and throws `std::invalid_argument` with a
  message that names the argument. The internal functions do not validate. The
  public function does it for them.
- Use plain types at the boundary: `bool` and a struct, not `std::optional<Struct>`,
  because not every binding converts `std::optional` easily.
- A new `SolarModel` enumerator needs a `SolarModelImpl` and a case in
  `internal::solar_model()`. Add the enumerator only when the model exists.

## Frames and conventions of the view

- Directions are `Horizontal` (azimuth from true north, clockwise; altitude). Inside,
  they are unit vectors in East-North-Up.
- The orientation quaternion rotates from the device frame to ENU, as the Android
  rotation vector does. The device frame is the Android one: x right, y up, z out of
  the screen, in the natural orientation. The back camera looks along -z.
- `ScreenRotation` has the meaning of Android `Display.getRotation()`: `rotation_90`
  means that the device is turned 90° counterclockwise (its top points left), so screen
  right = device -y and screen up = device +x. Do not derive it from
  `remapCoordinateSystem` examples: they remap the rotation matrix, which is the inverse
  relation, and the first version of the core had 90 and 270 swapped because of this.
- The heading offset rotates the sensor frame to true north: true azimuth = sensor
  azimuth + offset.
- Screen pixels: origin at the top left, y down. The camera parameters are in the pixels
  of the screen area, so the app converts the intrinsics of the sensor to the preview.
- The distortion is Brown–Conrady in the OpenCV direction (ideal to distorted). Check
  the direction of Camera2 `LENS_DISTORTION` against real images before you use it (M6).

## Precision

The tests compare the results with JPL Horizons. Each tolerance is the measured
maximum error plus a margin, and a comment gives the measured value. If you change a
model, measure again and update the comment. Do not increase a tolerance to make a
test pass without a reason in the comment.

## Conventions

- C++20 everywhere for now. The public headers must stay C++20.
- `std::array`, not C arrays. `const` for locals, parameters, and members that do not
  change. `std::ranges` where it is clearer.
- Define a free function from a header with its qualified namespace, in the
  reopened namespace. Keep file-local helpers in an anonymous namespace.
- Doc comments: `///` for functions, classes, structs, and enums. `///<` after a
  member or an enumerator. One or two lines: what it does, its preconditions, and its
  units. Units go into the names: `_deg`, `_s`, `_utc`, `_hpa`, `_c`.
- All times are Unix time in seconds (UTC), as `double`. The platform converts time
  zones.
